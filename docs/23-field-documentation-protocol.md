# Field Documentation Protocol

**Version:** Phase IV draft · 2026-05-17
**Status:** Drafted operating protocol before field visits, photography, video, audio, transcription or metadata capture

---

## Purpose

This protocol defines the sequence for field documentation. It applies to photography, video, audio, transcription, metadata capture, storage and review.

This protocol is drafted. It becomes implemented after named personnel, secure storage, consent records and review logs are in service.

---

## Role assignments

| Function | Required owner | Records produced |
|----------|----------------|------------------|
| Field lead | Founder or approved field coordinator | Field plan, consent checklist, visit log |
| Consent recorder | Consent coordinator | Consent notes and authority map |
| Documentation operator | Photographer, audio recorder, videographer or note taker approved for the visit | Capture log and media inventory |
| Practitioner reviewer | Practitioner or participant | Approval, restriction or revision decision |
| Community reviewer | Community authority when shared knowledge or place context is affected | Community review decision |
| Archive steward | Archive steward | Archive record, storage path, access tier and audit log |
| Governance reviewer | Governance steward | Escalation decision for high-risk cases |

No person may both capture restricted material and approve broader access unless the governance steward records the conflict.

---

## Pre-field gate

Field documentation may begin only after all items are complete:

1. Activity purpose recorded.
2. Individual, practitioner, community and site authority needs identified.
3. Consent brief delivered before the visit.
4. Compensation or reciprocity terms recorded.
5. Approved media types listed.
6. Prohibited media types listed.
7. Archive access tier default set to restricted.
8. Storage location prepared.
9. Withdrawal contact path provided.
10. Review dates assigned.

If one item is incomplete, field documentation is postponed or limited to non-recorded conversation.

---

## Capture protocol

| Stage | Action | Owner | Required record |
|-------|--------|-------|-----------------|
| Arrival | Re-state purpose, media types, stop rights and review rights | Field lead | Arrival consent confirmation |
| Setup | Label devices, confirm time sync and disable automatic cloud sharing if not approved | Documentation operator | Device checklist |
| Boundary marking | Identify no-record zones, no-photo objects, restricted methods and location limits | Practitioner or site authority | Boundary note |
| Capture | Record only approved media types and approved spaces | Documentation operator | Capture log with timestamps |
| Live restriction | Mark any item restricted when participant, practitioner or steward requests it | Documentation operator | Restriction flag |
| Pause | Stop capture when consent, safety or community concern appears | Field lead | Pause note |
| Closeout | Review captured material count, expected next review and withdrawal path | Field lead | Closeout note |

## Media-specific rules

| Media type | Before capture | During capture | After capture |
|------------|----------------|----------------|---------------|
| Photography | Shot list approved by practitioner or site authority | Avoid restricted objects, faces or locations unless approved | Create image inventory and mark image-level access tiers |
| Video | Segment purpose and setting approved | Stop for any instruction, restricted process or unrelated person entering frame | Create clip log with timecodes and review status |
| Audio | Interview topics and recording consent approved | Confirm off-record sections verbally and mark timestamp | Store raw file restricted and prepare transcript for review |
| Transcription | Language, translator and sensitive terms identified | Mark unclear or sensitive sections | Send excerpts or full transcript according to consent scope |
| Field notes | Note-taking consent confirmed | Keep private details out unless needed and approved | Separate public summary from raw notes |
| Metadata | Consent ID, place precision and access tier assigned | Do not capture exact coordinates unless site approval exists | Store metadata with archive record and review date |

---

## Metadata fields

Each field item must receive:

- archive ID;
- consent ID;
- material type;
- capture date;
- field lead;
- documentation operator;
- authority layer;
- place region;
- location precision;
- sensitivity;
- access tier;
- allowed uses;
- prohibited uses;
- reviewer;
- review date;
- withdrawal terms;
- storage location;
- public summary approval status.

Missing consent ID forces the item to sealed access.

---

## Storage protocol

| Time | Action | Owner | Completion criterion |
|------|--------|-------|----------------------|
| Same day | Transfer files to restricted storage | Documentation operator | File count matches capture log |
| Same day | Remove files from unapproved devices when transfer is verified | Documentation operator | Device cleanup marked complete |
| Within 2 business days | Create archive records and assign access tiers | Archive steward | All items have archive IDs |
| Within 5 business days | Prepare review packets without unapproved public copies | Documentation owner | Review packet logged |
| Within 10 business days | Send practitioner review packet when allowed | Consent coordinator | Delivery timestamp recorded |
| By review date | Record approval, revision, restriction or withdrawal | Archive steward | Access log updated |

Restricted material must not be stored in public repository paths, public drives, social platforms or messaging tools without archive steward approval.

---

## Review packet rules

Review packets must include:

- purpose of review;
- list of materials included;
- proposed use for each item;
- current access tier;
- requested access tier if change is proposed;
- caption, excerpt or summary text where applicable;
- deadline and non-response default;
- withdrawal and correction contact;
- note that no response keeps material restricted.

Review packets must exclude unrelated raw files and sensitive third-party material.

---

## Public release gate

The communications owner may publish only after the archive steward confirms:

1. consent status is active;
2. all authority layers approved the proposed use;
3. access tier is `public`;
4. public copy is separated from raw material;
5. caption, transcript excerpt or profile text has approval;
6. location precision matches site permission;
7. review date remains valid;
8. withdrawal path is recorded;
9. access log includes owner and timestamp.

If a public page changes the context of use, the material returns to review before publication.

---

## Incident response

When a field documentation concern appears:

1. Stop capture.
2. Mark affected files restricted or sealed.
3. Notify field lead and archive steward.
4. Record incident timestamp, material IDs and authority affected.
5. Notify practitioner or community authority when appropriate.
6. Decide delete, seal, restrict, revise or continue.
7. Log final action and next review date.

No field incident closes without an archive access decision.
