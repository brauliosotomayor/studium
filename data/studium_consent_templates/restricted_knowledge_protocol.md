# Restricted Knowledge Protocol

**Protocol status:** Draft operational protocol
**Use before:** Recording, storing, describing or representing sensitive cultural, ecological, trade, site or community-held knowledge

## 1. Restricted knowledge definition

Restricted knowledge includes information that a practitioner, community authority, land steward, site custodian or governance reviewer identifies as unsuitable for public release or broad archive access.

Examples include:

- teaching methods reserved for approved learners;
- trade processes or workshop techniques;
- sacred, ceremonial or lineage-governed material;
- ecological locations or seasonal harvest details;
- private routes, homes, workshops or fragile sites;
- community histories requiring collective review;
- knowledge shared for context but denied for documentation.

## 2. Default handling

Restricted knowledge receives `sealed` access unless a named authority assigns `community_only`, `practitioner_only` or `internal_restricted`.

Public release is unavailable unless the authority record explicitly names the exact excerpt, caption, image, clip, summary and audience.

## 3. Operational owners

| Function | Owner |
|----------|-------|
| Restriction identification | Field lead and practitioner or community authority |
| Restriction recording | Consent coordinator |
| Access tier assignment | Archive steward |
| Storage enforcement | Archive steward |
| Public copy prevention | Communications owner |
| Dispute escalation | Governance steward |
| Re-review | Original authority where reachable plus archive steward |

## 4. Field procedure

1. Ask whether any topic, object, method, location or person must remain undocumented.
2. Mark restricted topics before capture begins.
3. Stop capture when restricted material enters the frame, recording or notes.
4. Flag any accidental capture before storage.
5. Store flagged material as sealed.
6. Prepare review packet only if the authority requests review.
7. Delete, return, seal or restrict material according to the authority decision.

## 5. Metadata restrictions

For restricted knowledge, metadata must avoid:

- exact location;
- named non-public people;
- sensitive method labels;
- sacred or private terminology;
- routes or access instructions;
- dates that expose seasonal vulnerability;
- notes that explain how to reproduce restricted practice.

Use coded labels and secure private notes when metadata is required for audit traceability.

## 6. Access conditions

Access may be granted only when:

- consent ID exists;
- authority basis is recorded;
- access group is named;
- purpose is listed;
- review date exists;
- prohibited uses are listed;
- storage supports the tier;
- access action is logged.

If one condition fails, access is denied.

## 7. Revocation

Any granting authority may revoke access. The archive steward must:

1. suspend access within 2 business days;
2. identify affected archive IDs and public surfaces;
3. move material to `sealed`, `practitioner_only`, `community_only` or `withdrawn`;
4. record timestamp, owner, decision and next review date;
5. notify the requester of action taken where contact is available.

## 8. Public language rule

Public summaries must describe governed process and consent status without exposing restricted content. If a summary requires restricted details to be understandable, no public summary is released.
